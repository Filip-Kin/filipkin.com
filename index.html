I've been volunteering with FIRST for 7 years, and in that time I've attended 78 events. I've made some things to help my events run smoother, and my job easier.

FTA Buddy

ftabuddy.comGitHub

A field monitor and support tool for the technical crew at FRC events: FTAs, CSAs and scorekeepers. A Chrome extension on the field network reads the FMS and relays it to the cloud, so the field status is on everyone's phone instead of only the scoring table. Match logs are graphed per robot and can be shared with a team, CSA tickets and notes follow a team to its next event, and troubleshooting trees and a support chat built on the WPILib, REV and CTRE docs and past CSA threads help a volunteer who has not seen the problem before.

Svelte, Bun, tRPC, Postgres, Chrome extension

GitHub

Clients install and update themselves from the server.

FRC Radio Kiosk

The power board for the station that programs team radios at events. Version 1 is built. Version 2 is a 4-layer board for the new radio, designed in loon: it detects 802.3at PoE or falls back to passive 12 V, and CR123A cells keep the radio powered if the USB-C supply drops during a firmware update.

KiCad, STM32

Robot Vacuum

GitHub

A Makita robot vacuum I am retrofitting with a Raspberry Pi and an Arduino, about 40% done. The goal: a webcam reads AprilTags to find where the robot is, and it either follows a set path or plans the most efficient path over an area drawn in the web UI. Right now the Pi runs the drive, brush and fan motors, and I drive it with a gamepad from a web driver station, like an FRC robot.

Raspberry Pi, Arduino, Svelte, tRPC

loon

GitHub

AI-driven electronics design. You describe a circuit and Claude builds it: it picks parts, places modules like a buck converter or an ESP32 core, lays out and routes the board, and checks it with KiCad's own DRC. The output is plain KiCad files, and a hardware probe lets Claude read and drive pins on the real board. I designed the radio kiosk in it.

Bun, React, tRPC, KiCad
